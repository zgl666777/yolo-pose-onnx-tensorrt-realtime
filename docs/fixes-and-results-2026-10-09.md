# 修复与实测结果

本页保留早期修复与探索记录，最新结果及证据边界以 [当前验收状态](acceptance-status-2026-10-09.md) 为准。原代码备份在 `runs/before-fixes-2026-10-09/`。Ubuntu CPU 回放、真实摄像头 RTSP 软件停流恢复与一小时稳定性已补测；人工独立数据、Linux NVIDIA、物理 USB 与 8 小时证据仍待补齐。

## 已修复

- 跌倒告警修复：冲击帧短时遮挡不再清除刚捕获的运动证据；新增运动强度、有限保持时间和落地姿态约束。Windows RTX 4070 FP32 回放 `fall-01`、`fall-15`、`fall-30` 为 3/3 告警，`adl-01` 为 0 告警；慢速坐下和静态平躺回归不告警。证据 `runs/remediation/replay-fp32-v2/`。
- 精度声明纠正：旧 `models/pose-fp16-strict.engine` 把所有浮点层约束为 FP32，其 20 帧通过结果不能证明 FP16 骨干。新 `models/pose-mixed-strict.engine` 只降低末端人物分数卷积 `cv3.*.2/Conv` 为 FP16，骨干与姿态解码仍为 FP32；实际 Half 层见 `models/pose-mixed-strict.engine.layers.json`。20+70 张抽样严格通过，但全 11,936 帧检查 321 帧失败、整体未通过，见 `runs/remediation/precision-mixed-all11936.json`。原纯 FP16 失败对照保留，未将有限混合精度抽样通过称为完整验收。
- 人工审核草稿：`tools/build_review_draft.py` 生成 `data/urfall-review-draft/`，覆盖 70 段视频、11,936 个任务，官方粗标签只作提示，身份/框/四类姿态均为空且 manifest 标记 `authoritative:false`。

- 人工评估真值不再要求预测关键点。训练特征独立标记为 `pose_features`，不能当真值；提取保留全部人工实例、原始框、来源哈希、匹配 IoU 和漏检审计，禁止覆盖输入及旧输出。
- 两人漏检一人时计 1 FN、站立 recall=0.5；预测框偏移保留人工框误差，IoU 不会被覆盖为 1。这两项有专门回归验证。
- 模型/分类器初始化纳入失败摘要保护，原生 ONNX 异常也能保存 `summary.json` 和失败阶段。重建与关闭异常记录到 `health.jsonl`，重建失败继续消耗有限重试直到恢复或耗尽。
- 精度对照使用基线可见关键点测位置误差，同时记录可见性丢失/增加；每个检测少于 4 个基线可见点视为证据不足，不能通过姿态后处理验证。
- 跟踪评估增加每人匹配段、碎片和 ID 切换；“一个人六帧六个 ID、纯度仍为 1”的回归现在报告 5 次碎片与切换。
- 时序检测接受坐姿作为跌倒前支撑状态，有坐姿→平躺告警回归。静态平躺和单帧噪声抑制继续通过。主动躺下仍需真实负例验证。
- 真实数据必须使用预先冻结且身份已审核的划分，验证共享人/视频隔离、标签、原始框和源哈希。train 拟合、validation 调 C，训练不评分 test；最终评分是独立命令，检查模型和测试特征哈希。
- 记录配置、模型、动态库、输入、代码 SHA256，OS/CPU/GPU/驱动/Python/全部包版本及可读取工具链版本。GPU 后端增加每秒整卡显存/利用率/温度原始 CSV。
- 告警媒体时间与包含主机处理时间的输出延迟分别记录；输出计时截至事件写入调用，不含 flush 或上游缓存。
- 修复 Windows 含中文路径下 OpenCV 图片读写失败，避免本项目目录中的精度图/预览静默丢失。

验证：`runs/fixes-tests-final.log`、`runs/fixes-tests.xml`，**52 项通过**，启用真实 GPU/C++ 测试。额外编译检查通过。格式校验中使用的模拟姿态数据仅是回归样本，不是真实训练成绩。改动前后 SHA256 清单见 `runs/change-manifest.json`，最终环境与代码哈希见 `runs/final-environment.json`。

## 数据交付

从[URFD 官方](https://fenix.ur.edu.pl/~mkepski/ds/uf.html)下载 **70 段真实拍摄视频**，包含 30 次演示跌倒和 40 段日常活动。总共 142 个文件，约 98 MB，均已成功下载；文件哈希、来源、许可、尺寸和帧数见 `data/urfall/download-manifest.json`。另保存官方原网页快照和原始深度姿态标签。

许可是 CC BY-NC-SA 4.0，限非商业学术用途。应按发布页引用 Kwolek & Kepski 2014 论文，商业用途联系发布方。

`data/urfall-review-complete/` 提供 **1,827 个待标注帧任务**、11,544 条官方粗标签和暂定事件边界。人物身份、RGB 框及四类姿态没有捏造；身份登记表留空，待审任务会被训练/评估校验拒绝。它们是标注准备材料，不是完成的人工测试集。全流程测试还需密集覆盖全部人物与帧。

官方 -1 仅表示非平躺，无法区分 standing/sitting；0/1 来自深度帧，需要复核 RGB 时间对应。跨视频人物身份未提供，不能以“每段视频一个新人物”假装满足独立划分。坐姿跌倒、主动躺下、跪地等定义和复核规范见 [真实数据与验收流程](data-and-acceptance.md)。

## 早期 Windows 视频对照

在 RTX 4070 Laptop GPU 上，以 fall-01、fall-15、fall-30、adl-01 四段视频进行早期探索；这些样本随后用于规则修复回归，不能作为冻结独立最终测试。每种后端独立实时回放，输入时钟/丢帧可能导致分类差异，原始预测均保留。

证据目录 `runs/real-video-windows-v2/` 包含配置、软件/硬件与文件哈希、逐帧日志、原始输出、告警、GPU CSV、基准和执行命令。

| 后端 | 预热后模型调用 FPS | 四段平均系统 FPS | 官方粗标签 macro F1 | 探索性事件 TP/FN |
| --- | ---: | ---: | ---: | ---: |
| ONNX CPU | 38.66 | 26.02 | 0.3678 | 0/3 |
| TensorRT FP32 | 251.10 | 25.95 | 0.3695 | 0/3 |
| TensorRT FP16 | 313.37 | 26.08 | 0.3675 | 0/3 |
| C++ FP32 | 242.72 | 25.81 | 0.3679 | 0/3 |
| C++ FP16 | 305.83 | 26.06 | 0.3739 | 0/3 |

基准为 20 次预热/200 次推理，包含传输、不含全流程。系统 FPS 受源帧率和短视频初始化限制，不能用 313 FPS 描述摄像头吞吐量。报告中的分类是官方 not_lying/falling/lying 三类、445 个粗标签实例，采用“最大检测框对应单演员”的探索性关联，**没有人工框匹配、人物独立性和最终四类真值**。详见 `official-coarse-report.json` 的限制。

上述早期版本在 **3 段跌倒中均未告警，TP=0、FP=0、FN=3**；90 个 falling 标签实例 recall=0。后续时序修复的四视频回归已变为 3/3 告警、ADL 0 次，见 `runs/remediation/replay-fp32-v2/`；这只证明探索样本回归改善，不能由此推出独立准确率。

真实帧精度对照采用 4 视频各 5 帧，共 20 张：PyTorch/ONNX 和 FP32/ONNX 各 20/20 全部通过默认阈值；FP16 原始坐标 0/20、原始分数 0/20，最大 raw 坐标绝对误差 10.93085 模型像素；20/20 后处理通过（包含新的可见性检查）。整体精度验收保留失败，未放宽阈值。证据为 `precision.json`。

## 本机摄像头初测

HP True Vision FHD Camera（source 0）读取成功，640×480。TensorRT FP16 连续运行 300 秒，使用未训练规则分类器，未保存摄像头原始视频。

- 运行总时长 301.41 秒，处理 8,938 帧，系统 29.65 FPS，丢弃 2 帧，0 推理故障，0 重连，采集线程正常退出。
- 主机延迟 P50 11.22 ms、P95 18.20 ms；从读取完成开始，未包含设备上游缓存。
- RSS 峰值 544.19 MB，首尾十分之一段增加 6.85 MB，拟合趋势约 +1.55 MB/分钟。该短测不足以确认泄漏或长期稳定。
- 整卡显存峰值 1,677 MB，含桌面及其他应用，不代表本进程独占。

证据：`runs/live-camera-300s/{summary.json,performance.json,frames.csv,gpu.csv,health.jsonl,provenance.json}` 和 `runs/live-camera-300s.log`。5 分钟不是小时级或 8 小时验收，也没有物理拔插。
